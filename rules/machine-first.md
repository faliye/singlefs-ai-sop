# 机器优先：先分清「可读」与「可验证」

很多软件工程的通行准则，是在**「一个人要把整套东西装进脑子里」**这个前提下长出来的。
那个前提正在失效：代码由人与模型协作产出，而读代码这件事本身也可以交给模型。

**本工程不默认继承这些准则。** 每一条都要重新过一遍判据，过不了的就放弃。

## 姿态：怀疑地继承，不是默认地继承

对既有「最佳实践」的默认态度是**存疑**，不是遵守。

理由很直接：**这些准则里有相当一部分，本质上是在人脑算力有限的前提下，
用来托住工程质量下限的**。它们校准的是人的极限。
而现在机器的算力早已越过那条线，**照着旧极限设的下限，就成了太低的下限**。

不是说它们都错了——是说它们的**理由要重新查一遍**，
不能因为「大家都这么做」就继续做。

## 这条姿态的前提，以及怎么推翻它

「机器的算力早已越过那条线」是整套方法论的地基。**它是可证伪的经验断言，不是信条。**
所以这里写明它依赖哪两条前提、以及什么现象会推翻它——
**要反驳这套姿态，靶子是这两条前提，不是「放宽的」与「留下的」那两张表。**

### 前提一：上下文窗口已到 2×10⁵ ~ 10⁶ token 量级

200K / 500K / 1M 三档。1M 档一次装得下一个 crate 连同它的测试、kb 与决策记录。
依据：本仓这一轮工作就跑在 1M 档的会话里。别家的数字不写进来——现查不了的数字不算证据。

**口径**：这是**宣称的窗口上限**，不是「在整个窗口上保持同等准确率」。
长上下文的中段召回衰减是已知现象，本工程没有实测过它在多大规模上开始咬人。

- **它撑起的**：「PR 要小」「概念要少」「DRY 靠人同步」这三条的放宽——
  它们的原始理由全是「一次装不下」，而这个理由在 1M 档上不再自动成立。
- **它撑不起的**：「推理范围要有界」不在放宽之列。窗口大了但**仍然有限**，
  且准确率随距离衰减——所以模块边界与显式契约比过去更值钱，不是更不值钱。

### 前提二：并发交错已经可以被穷举判定

「这个屏障够不够」这类判断，**直觉给不出可复核的答案**。现在它拆成两半：

| 谁做 | 做什么 | 精度 |
|---|---|---|
| herd7 / LKMM | 在给定内存模型下**穷举**所有允许的交错，给 Never / Sometimes 判定 | 对写下来的那个 litmus 是完备的 |
| 模型 | 把代码里的同步模式翻成 litmus、枚举该问哪些场景 | **不完备——缺口在这里** |

**口径**：精确的是工具，不是模型。工具只回答你写下的那个 litmus，
「有没有漏掉一个该问的场景」没有任何东西保证。
所以 `scripts/lkmm.sh` 强制两侧对照组：只有 Never 没有 Sometimes，
分不清是屏障挡住了，还是这个模式本来就撞不上。

- **它撑起的**：「穷尽性是可机检的」，以及由它推出的「宁可写穷举的显式分支」
  和「路径数有界就可验证」。

### 前提失效时，收回哪几条

前提不是永久的。观测到下面任一现象，对应的放宽当场收回：

| 观测到什么 | 收回什么 |
|---|---|
| 模型在本工程实际规模上丢中段事实——漏掉一条已经在上下文里的约束 | 「PR 要小」的放宽，重新按装得下的粒度切 |
| 生成的重复代码与生成器对不上 | 「DRY」的放宽，回到不许重复 |
| litmus 判定与真机压测结论矛盾 | 「穷尽性可机检」，`lkmm.sh` 降级为参考，不再当门禁 |

**这张表就是本文件的反推**（`evidence-discipline.md`）：
说不出「什么现象会推翻它」的前提不是前提，是信仰。

## 遇到一条通行准则，走这个流程

1. **问它原本要解决什么问题。** 说不出来的，直接放弃——
   说不出理由的规矩本来也守不住。
2. **问那个问题今天还在不在。** 如果它当初解决的是「人记不住」「人读不过来」
   「review 带宽不够」，那多半已经不在了。
3. **问它有没有第二个理由。** 很多规矩恰好还顺带解决了一个与人无关的问题
   （见「留下的」那张表）。有 → 留下，**并且把理由改写成那个**。
4. **改写后的理由要能落到门禁上。** 落不下来的，降级为建议，不写成规矩。

## 判据

> **这条规则是让代码更容易被机械验证，还是只让它更容易被人眼扫过？**

- 只让人眼舒服 → **可以放弃**
- 让验证更容易 → **留下，但理由要重写**——别再挂在「可读性」上，
  挂在「可读性」上的规矩，下一次有人问「为什么」时就守不住了

## 放宽的（人脑带宽的产物）

| 旧准则 | 它原本的理由 | 处置 |
|---|---|---|
| 设计要统一、概念要少 | 维护者要装得下 | **放宽**——这正是「一棵树装下所有东西」的由来 |
| DRY，避免重复 | 改一处要同步改多处 | **放宽**：同步修改是机器强项。但重复要**生成**，不要手抄 |
| PR 要小 | review 带宽 | **放宽**——可二分、可回退仍然要保 |
| 避免过早优化 | 人的时间预算 | 降级为建议 |
| 函数要短到一屏 | 短期记忆与屏幕高度 | **保留，理由改写**：按「一件可独立验证的事」定长度，不按屏幕定 |
| 嵌套要浅 | 人的解析能力 | **放宽**：层数不设限。真正的约束是**路径数**——循环嵌套几乎不增路径，条件嵌套按指数增。详见 `engineering-philosophy.md` |
| 命名要自解释 | 给下一个人看 | **保留，理由改写**：命名是信息不是装饰，模型也补不回被省掉的语义 |

⚠️ 「函数要短」「命名要自解释」这两条最容易被本规则误伤。**放宽的是「为了让人装得下而做的压缩」，
不是「让含义显式」**——后者对模型同样是增益。详见 `engineering-philosophy.md`
的「AI 友好 ≠ 不可读」。

## 留下的（与谁读代码无关）

| 准则 | 真正的理由（重写过的） |
|---|---|
| 崩溃一致性、不变量 | 是物理，不是心理 |
| 磁盘格式兼容 | 对外的永久契约，改不掉 |
| 测试可复现 | 任何判断的前提，人机皆然 |
| 故障域隔离 | bug 的爆炸半径与谁读代码无关 |
| 可二分、可回退 | **改动量越大，这两条越值钱**，不是越不值钱 |
| 模块边界要有显式契约 | **没有契约就没法单独验一块** |
| 推理范围要有界 | **增量验证要求推理范围有界——上下文窗口也是有限的** |

最后两条最容易被当成「可读性」丢掉。它们不是。

## 推论：那就该这么写代码

- 宁可写**穷举的显式分支**，不写聪明的通用路径——**穷尽性是可机检的**，
  「一个函数搞定所有情况」不是
- 宁可用**类型让非法状态无法表示**，不写注释解释约束
- 宁可把**不变量写成断言**，不写进文档
- 宁可**生成**重复代码，不手工维护重复
- 注释写「为什么这样」，不写「这在做什么」——后者机器自己读得出来

## 这两条教条长什么样：代码示例

前两条推论最常被争执，所以把它们写成可以直接指认的形态。
争执一般起于「这条分支有必要吗」——**判据不是必要性，是穷尽性谁来检查。**

### 教条一：穷举的显式分支胜过聪明的通用路径

```rust
// ✗ 通用路径：新增一种情形时，编译器什么也不说
fn node_size(dev: &Device) -> u32 {
    if dev.rotational { 64 * 1024 } else { 16 * 1024 }
}
```

```rust
// ✓ 穷举分支：新增 Zoned 之后不补这里就编译不过
enum Medium {
    Rotational,
    Ssd,
    Zoned { zone_size: u32 },
}

fn node_size(m: &Medium) -> u32 {
    match m {                       // 关键在于**没有** `_ =>` 通配臂
        Medium::Rotational          => 64 * 1024,
        Medium::Ssd                 => 16 * 1024,
        Medium::Zoned { zone_size } => (*zone_size).min(256 * 1024),
    }
}
```

**要害是那条没写的 `_ =>`。** 加上通配臂，代码看起来更短、更「通用」，
而它恰好把编译器的穷尽性检查关掉了——新增一种情形时，
程序会安静地走进通配臂，行为错误而没有任何人报警。

**所以判据不是「分支多不多」，是「漏掉一种情形时谁会先发现」**：
是编译器，还是生产环境。前者 → 显式分支；后者 → 那不是通用，是把检查删了。

### 教条二：用类型让非法状态无法表示

```rust
// ✗ 同一种底层类型承载多种含义：混用编译通过，运行期才错
fn read_block(addr: u64) -> Block;
fn free_extent(start: u64, len: u64);
// 调用点把逻辑地址传成物理地址，编译器无话可说
```

```rust
// ✓ newtype：混用编译不过
#[derive(Clone, Copy, PartialEq, Eq)] pub struct Lba(pub u64);  // 逻辑地址
#[derive(Clone, Copy, PartialEq, Eq)] pub struct Pba(pub u64);  // 物理地址

fn read_block(addr: Pba) -> Block;
// read_block(Lba(x)) 直接编译不过 —— 一整类运行期 bug 变成编译期错误
```

再进一步，**把「还没验证过」也做成类型**，让「忘了验证」无法表示：

```rust
// ✗ 用布尔字段表达状态：忘了检查它，编译器不管
struct Node { bytes: Vec<u8>, checksum_ok: bool }

// ✓ 用类型表达状态：没验过的东西根本拿不到已验过的那个类型
struct RawNode(Vec<u8>);        // 刚从盘上读出来，未验证
struct VerifiedNode(Vec<u8>);   // 校验和已比对通过

impl RawNode {
    fn verify(self, expect: Checksum) -> Result<VerifiedNode, CorruptBlock> { /* ... */ }
}

fn walk(node: &VerifiedNode) { /* ... */ }   // 想跳过验证就构造不出入参
```

**这两条教条是同一件事的两面**：教条一让「漏掉一种情形」被编译器抓住，
教条二让「非法组合」根本写不出来。**两者都是把检查从人转移给机器**，
而这正是 `machine-first.md` 的判据——**让代码更容易被机械验证**。

### 什么时候不该套用

**这两条对「可删除的东西」无脑成立，对「删不掉的东西」要另算。**
代码分支写错了可以删；而写进对外契约（磁盘格式、协议、公开 API）的分支删不掉，
此后每一个实现都要永远支持它。那一侧的判据要另外定，
不能拿「显式分支更安全」一句话推过去。

## 一条反向的提醒：文档纪律不在放弃之列

`doc-discipline.md` 那套（正文只写现状、历史进文末、决策记录进 kb）
**不是人脑带宽的产物**。

一份混着历史的文档，**模型比人更难分辨哪个是现行值**——
它没有「我记得上周改过」这种线索，只能全盘当真。
**陈旧或自相矛盾的文档对模型的伤害不比对人小，只会更大。**

同理，`kb/decisions.md` 的价值也在上升而不是下降：
它是唯一能告诉后来者（人或模型）「这条为什么是现在这样、什么依据」的地方。
