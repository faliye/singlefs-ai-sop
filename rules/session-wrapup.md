# 收尾：每轮工作结束前必做

## 0. 报进度——排在最前，不许省

一行三个数：**当前在哪个里程碑 / 门禁过不过 / 还缺什么证据**。
状态一律现查（跑 `gate.sh`），不许从上一轮笔记里抄。

**同时说清这一轮给这个数加了多少。** 常常是 0：出了个零结论、
推翻了一条决策、或者只是查明了一个还拿不到的证据。**那就写 0。**
把别轮的成果算进本轮，等于把进度表变成一个只涨不跌的东西，它就不再有用了。

## 1. 这轮敲的脚本/命令，有没有该收归 `scripts/` 的？

判据是「**会不会被抄第二遍**」，不是「写得好不好」。

**踩过的坑做成会失败的检查，不要做成提醒句。**
写一句「注意别在 X 时候做 Y」拦不住手敲命令，
一个在那时**直接拒绝执行**的检查才拦得住。

反方向也看一眼：有没有已经没人用的，该删就删。

## 2. 这轮用到的 skill / 规则，有没有该改的？

有没有哪一步是靠记性兜住的、判据是不是事后才补的、同样的样板是不是又抄了第三遍。
**有就当场改那个文件**，别留到「下次」。

改哪里，看这条管的是什么：

- **管协作**（证据、文档、决策落点、门禁反馈）→ 改 singlefs-ai-sop
  （`rules/` / `skills/` / `scripts/`），并抬 `VERSION`
- **管文件系统怎么设计** → 改项目本地的 `kb/`、`.claude/rules/` 或项目 `CLAUDE.md`

**拿不准就放项目本地。** 这套 SOP 只有 singlefs 一个使用者，
「别的项目会不会也需要」不是判据——没有别的项目可看，那句话谁都能答「会」。

## 3. 决策有没有变动？

这轮如果推翻或定下了任何设计决策，**当场写进 `kb/decisions.md`**，含推翻依据。
决策记录漏一条，三个月后就要靠考古回答「我们当初为什么这么定」。

**一次论证判决也是一次决策变更。** 权衡完给出「这条现在不该定」「维持原方案」
这类结论时，如果它实质上推翻了 `kb/decisions.md` 里已经写下的某句话，
那就是一次推翻，同样要当场记进去、含依据。
判决藏在对话里而决策文件不动，三个月后没人知道那句话为什么不算数了。

## 4. 同一个仓里有没有别的会话在飞？

多个会话并发作业时，三个默认前提会失效。收尾前逐条对一遍：

- **「工作区里的都是我的」不再成立。** 提交前把改动按「本轮 / 非本轮」分拣，
  只提交本轮的文件；把别的会话的半成品卷进提交，等于替别人发布了没验完的东西。
- **「门禁红了 = 我改坏了」不再成立。** 判红先看失败涉及的文件在不在本轮改动里；
  不在，就如实报「红，但不是本轮的」，不要顺手修——那是别的会话没做完的收尾。
- **公共编号先到先得。** 历史条目序号、实验号这类公共编号，取号前先查已有的最大号；
  改公共文件只做定点替换，不整文重写——重写会把并发会话已写进去的东西静默抹掉。

撞过的号能做成会红的检查就做成检查（`rules/show-me-test.md`
「踩过的坑要做成会失败的检查」），项目侧照着历史文件的编号形态写就行。
