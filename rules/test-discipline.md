# 测试纪律

## 单次观测不算数

N≥5 轮，判「通过」要全通过、判「失败」要全失败（**门槛不对称**）。
两侧都不满足就如实报「不稳定」，不下结论。

**适用前提：观测内在有变异**——真实 I/O、并发、时序、随机源，至少占一样。
一样都不占的是确定性模型：同一个二进制跑 N 遍必然逐字节相同，
**N=1 与 N=5 提供的信息量相同**，「N 轮一致」写出来只是把确定性
包装成了压测那一级的证据强度。实测：三个纯算术实验都写过「N=5 轮逐字节一致」，
后来整批被复核打回。

⇒ 确定性实验要写只能写成「跑 N 轮证明的是没有隐藏状态，不是统计稳定性」；
它的证据强度不来自轮数，来自变异测试与钉绝对值的断言。

## 读不到 ≠ 读到 0

指标读空必须重试并**整轮作废**，绝不当成 0 参与判定。

## 崩溃一致性只能靠崩溃点重放验证

记录块层全部写请求，在**每一个**可能的崩溃点截断、重放、跑 checker。
**没跑过这个的写路径，不算验证过**——单测全绿不构成任何崩溃一致性证据。

## 功能正确性靠模型对拍

内存里维护一个「理想文件系统」（就是个 HashMap，不管性能不管崩溃），
随机操作序列同时施加到模型和实现，比对。

**这是本工程唯一的功能 oracle。** 从零设计意味着没有参照实现可比对——
移植类项目那种「拿现成工具的输出当标准答案」的便利这里不存在，必须自己造。

## 实验开跑之前，答案不许已经存在

**禁止预设结论，也禁止在设计阶段参考任何已有结论**——本工程上一轮的结论、
别处的定论、自己的直觉预期，一概不看。

理由是机制性的：判据一旦是照着预期结论定的，它就只会在「符合预期」时判通过。
**这与「失败条款不许让结论不可证伪」是同一个病，只是病灶提前到了设计阶段**——
那时还没有任何数字，改判据不留痕迹，事后也看不出改过。

**要读的是定义，不是答案。** 被测对象的口径、参数、语义必须逐字读
（`verify-before-claiming.md`「它定了没和它到底怎么定义的是两个问题」）；
而「上一轮测出来是 X」「某某项目说这样更快」是答案，读了等于给自己发了标准答案。

**做法**：判据、阈值、作废条款全部在跑之前写死，写完再去看已有结论。
两者不一致时如实并列，不许回头改判据——**改了就是新实验，重跑。**

## 实验的失败条款不许让结论不可证伪

写实验时最容易犯、也最难自己发现的一个错：**把「没测出效应」定义成实现 bug**。

这么一写，实验就只可能产出支持性证据——测出效应记为发现，
测不出记为「实现坏了，整轮作废」，**没有任何观测能推翻结论**。

正确写法是把两件事分开，**两个对照组都要跑**：

| 对照组 | 作用 | 测不出差异时怎么判 |
|---|---|---|
| **阳性对照**：效应在文献里确凿存在的那个基线 | 证明测量有判别力 | **实现有问题，整轮作废** |
| **真实基线**：本工程实际打算实现的那个方案 | 回答实验真正要问的问题 | **合法结果，如实记录** |

少了阳性对照，「没有优势」分不清是结论如此还是实现坏了；
少了真实基线，测的是「有没有这个机制」，不是「这个机制比已有的多买到什么」。

## 阳性对照必须对**每一条**被测的臂都跑

一个实验有 N 条臂时，阳性对照只跑其中一条，**等于另外 N−1 条从没过闸**——
而产出结论的往往正是没跑的那一条。

实测：一个实验有两条规则臂，阳性对照只对第一条跑了；补跑后**第二条在对照负载上就出错**，
按该实验自己的作废条款它当时就该整轮作废，而它产出的数字已经被写进决策文档。

**做法**：对照的循环必须遍历臂的集合，不许写成「取第一条跑一下」。
臂是后来加的时候尤其危险——加臂的人通常只改被测那一段，不会想起来对照那一段。

## 只让多条臂互相比，测不出「所有臂一起错」

**臂之间的相等是弱判据**：它只排除「某一条臂单独错了」，
排除不了「同一个公式被所有臂共用，而那个公式是错的」。
后者在互比里长得和正确一模一样——**全部相等**。

⇒ **每一条互比断言旁边，必须有一条把绝对值钉死的断言。**
「三条臂的开销相等」不够，还要有「开销恰好等于 N」，N 由独立的算术推出。

实测：一个三臂实验，18 个单测、一道守恒检查、一组阳性对照，
**全部只做臂间互比**。变异测试连做三轮，每轮都有「一个测试都没红」的条目，
暴露的都是同一个形状：把区间参数乘 2、把记录计费换个口径、
让某条臂一次发布都不做——三条臂**一起**跟着错，互比仍然相等。
其中一条错误让某条臂在 20 万次操作里**一次根都没发**，而没有任何检查报警。

**做法**：写完一条互比断言就自问「如果三条臂**一起**错了，谁会发现」。
答不上来就补一条钉绝对值的。**这与「阳性对照必须对每一条臂都跑」是同一条纪律的两面**——
那条管「每条臂都过闸」，这条管「闸本身不是相对的」。

## 变异测试证明的是断言会红，不是覆盖

变异只作用在**已经写了断言的那些函数**上。它证明的是
「每处已写断言的代码都被变异测过」，**不是**「结论覆盖的每处代码都被测过」。

⇒ 禁写「零盲区」，只许写「N 条变异全部被抓」；写完结论回头问一句：
**这条结论的算术来源被断言覆盖了吗？**
实测：一个实验声称「9 条变异全部被抓、零盲区」，
而它结论的算术来源零单测零变异，算错了不会有任何报警。

两个会让变异静默失效的坑：

1. **常量断言写加法，不写减法。** `assert_eq!(A - B, 240)` 被变异把常量改大就**编译期溢出**，
   被记成「无效变异」而不是「被抓到」——一条本该会红的断言静默失效。
   写成 `assert_eq!(A, B + 240)`，两侧才都活到运行期。
   实测：两条被记成无效的变异，改写成加法后都变红。
2. **等价变异不是盲区，分开记。** 在全部输入上与原式同值的变异永远抓不到，不算漏。
   判定为等价的，把等价性写成一条测试留档，再换一个真会改行为的变异补位。

## checker 即规范

不变量清单每加一条，checker 就加一个检查。
**「这个格式是什么」的权威答案是 checker 的源码，不是文档。**

## 检查本身也可能是错的

断言前先确认检查**有判别力**——例：验「没有非法块」时，
要同时确认扫描确实读到了块，否则查不到可能只是因为根本没扫到。

写完一个检查，问：如果被测对象真的坏了，它会不会红？答不上来就还没写完。

## 阴性结果要能和「代码没跑到」分开

「没复现」不等于「没问题」。要说「这条路径是对的」，
得有读数证明那条路径**真的执行了**。
