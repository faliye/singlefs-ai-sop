# 进程与命令规范

## `pkill -f` / `killall` 一律禁用

模式串会出现在 wrapper 自己的命令行里，**杀掉自己的 shell**。

要停进程：先 `ps` 列出、看清楚，再用**字面量 pid** 分第二条命令杀。
统计类改用 `/proc` 结构化判据并排除自身进程树。

## QEMU 虚机必须把 pid 写进文件

销毁时按文件里的字面量 pid 杀，不许按名字匹配。
虚机跑飞了会占满内存，而按名字匹配会连带杀掉别的测试。

## 别用 echo 假装命令成功

`cmd 2>/dev/null; echo "已完成"` 里那句 echo **无条件执行**，
sudo 失败时它照样打印「已完成」。

改状态的命令必须**回读实际状态**验证：
`systemctl stop X` 之后要 `is-active` 确认，不能只看 stop 的退出码。

## 结果抓取要有完整性闸

被测程序打印结果、外面的脚本抓回来——**这条路上丢一行是静默的**。
控制台会被 BIOS 转义序列、内核日志、串口噪声污染，
按行首锚定（`grep '^ANCHOR'`）会把行首被顶掉的那一行悄悄漏掉，
外面看到的是「少了一项」，不是「出错了」。

**做法**：被测程序在收尾行报出它一共发了多少条，抓取方比对条数，对不上整轮作废。
这道闸自己也要先证明会红——喂一个声称发 N 条、实际只发 N−1 条的假程序，它必须判红。

## 子 shell 里的赋值传不回父进程

`rc="$(run_one ...)"` 这种写法里，`run_one` 内部对变量的赋值**在父进程里是空的**。
结果抓取若依赖那个变量（例如日志路径），就会永远抓到零条，而退出码是 0——
又一个绿着灯出错。**要传值就落文件，不要靠变量。**

## 脚本改文件之后要回读确认，警告是免费的信号

用脚本做字符串替换改代码或文档时，**匹配不上不会报错，只会什么都不做**。
缩进差一个空格、引号变了体、行尾多个空格——替换静默失效，而退出码是 0。

**做法两条**：
1. **替换必须断言命中**：替换数为 0 就报错退出，不许「改完就当改了」。
2. **改完回读**：grep 一下新内容在不在，或直接跑一遍看行为变没变。

⚠️ **编译器与 linter 的警告是这一类失效最便宜的信号，不许略过。**
实测：一次替换因缩进不匹配没生效，于是一个方法成了死代码，
编译器每次构建都在报 `never used`——那条警告被略过了整整一轮，
而基于那段代码得出的结论**方向是反的**。

## 管道里的退出码不是你想要的那个

`cmd | head` 之后取 `$?`，拿到的是 `head` 的退出码，不是 `cmd` 的。
`cmd | grep x && do_something` 同理——判的是 `grep` 成不成功。

后果是**失败被吞掉**：`cmd` 已经挂了，而脚本继续往下走，
后面每一步都基于一个不存在的结果。

**做法**：要判前一段的成败，用 `${PIPESTATUS[0]}`，或者干脆不接管道——
先把输出落到变量或文件，判完退出码再处理。

## 测试镜像一律放临时目录

不许放仓库内。几个 G 的镜像误提交进 git 是不可逆的麻烦。
镜像路径统一从环境变量取，默认落到 `${TMPDIR:-/tmp}`。

## 破坏性操作先看清楚再动

`mkfs` / `dd` / `dmsetup remove` 打错设备名会毁掉真实数据。
**目标设备必须来自变量且先 `lsblk` 打印确认**，不许硬编码 `/dev/sdX` 字面量。
