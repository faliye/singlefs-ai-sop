# 所有结论要三次推导：正推 / 反推 / 校验

**任何结论在说出口之前，必须走完三步，并说清每一步是什么。**
少任何一步，它就叫假设，写成假设，不许写成结论。

| 步 | 问什么 | 做不到就是没做 |
|---|---|---|
| **正推** | 从机制 / 代码 / 数据推到结论 | 说得出「哪条命令、哪几行代码、哪个数据文件」 |
| **反推** | **假设这个结论是假的，那我本该看到什么？** 然后去看 | 说得出一个**具体的、本轮做得到的**观测，以及它没出现 |
| **校验** | 换一条独立路径复现同一个判断 | 两条路径**不共享**同一段代码、同一次采样、同一个工具 |

反推是最常被跳过的一步，而它恰恰最值钱：正推只能告诉你「这个解释说得通」，
反推才能排除「另一个解释也说得通」。

## 校验路径本身也要证明它会红

「换一条独立路径复现同一个判断」还不够——**那条独立路径自己也可能是摆设**。

两条路径给出一致的结果，可能意味着「都对」，也可能意味着**第二条根本没在看**。
不注入故障就分不开这两种情况，而**它们看起来一模一样：都是一致**。

**做法**：往被测对象里注入一个**已知的、本该被第二条路径抓到的**故障，确认它真的抓到了。
抓不到，那条校验路径就是装饰，此前所有「两条路径一致」的记录一并作废。

例：用内核的块层计数器去校验程序自己数的 I/O 次数，两者逐格一致。
这个「一致」只有在**摘掉直接 I/O 之后、块层计数归零而程序计数纹丝不动**被观测到之后，
才构成证据——否则那个一致也可能是第二条路径在回声第一条。

**这与「每个验证都必须能失败」是同一条纪律作用在校验路径上**：
主检查要证明会红，校验路径同样要证明会红。**只证明前者，等于只做了一半。**

## 喂给多方论证的背景材料，本身要先核

找多个独立来源交叉验证一个推论时，通常要先写一份「已知事实」交给各方。
**那份材料里的每一条外部事实，提问者自己要先核过。**

理由是机制性的：**各方都以它为前提，所以材料里的错误会被所有方一起继承**，
而它们仍然会给出「一致」的结论——**一致因此不再是证据**。

实测：一份背景材料里写着某个现役实现「没有某个字段」，
其中一方自己查到了相反的原文，**却仍然沿用材料里的说法作对照基准**。
最终的一致，是三方一起继承了同一个错误。

**做法**：材料里凡是「某某实现是这样的」这类句子，写进去之前自己现查一遍；
核不动的就标明「未核实」，让各方知道那一条不能当前提用。

## 一个假设要能被观测否掉，否则它不是假设

写下假设之后，**先问「什么现象会推翻它」**，答不上来就说明它还没成形，不要拿去建实验。

**排除一个假设，要么有可证伪的观测，要么明说是推的。**
「我想不出别的解释」不构成排除。

## 文件系统特有的反推缺口

本工程的多数被测量是**对 / 不对**这样的二值现象。风险不在测量精度，在覆盖：

- **「测试全绿」不等于「实现正确」。** 崩溃窗口可能只有一次写宽，
  没撞上可能只是没遍历到那个崩溃点。要说「崩溃一致性成立」，
  得说清这一轮**本来撞得上吗**——枚举了多少个崩溃点、是不是全部。
- **「checker 没报错」不等于「镜像是好的」。** 也可能是 checker 还没实现那条检查。
  说这句话之前先看 `kb/invariants.md` 里对应条目的实现状态。
