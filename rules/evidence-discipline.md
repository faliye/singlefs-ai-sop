# 所有结论要三次推导：正推 / 反推 / 校验

**任何结论在说出口之前，必须走完三步，并说清每一步是什么。**
少任何一步，它就叫假设，写成假设，不许写成结论。

| 步 | 问什么 | 做不到就是没做 |
|---|---|---|
| **正推** | 从机制 / 代码 / 数据推到结论 | 说得出「哪条命令、哪几行代码、哪个数据文件」 |
| **反推** | **假设这个结论是假的，那我本该看到什么？** 然后去看 | 说得出一个**具体的、本轮做得到的**观测，以及它没出现 |
| **校验** | 换一条独立路径复现同一个判断 | 两条路径**不共享**同一段代码、同一次采样、同一个工具 |

反推是最常被跳过的一步，而它恰恰最值钱：正推只能告诉你「这个解释说得通」，
反推才能排除「另一个解释也说得通」。

## 校验路径本身也要证明它会红

「换一条独立路径复现同一个判断」还不够——**那条独立路径自己也可能是摆设**。

两条路径给出一致的结果，可能意味着「都对」，也可能意味着**第二条根本没在看**。
不注入故障就分不开这两种情况，而**它们看起来一模一样：都是一致**。

**做法**：往被测对象里注入一个**已知的、本该被第二条路径抓到的**故障，确认它真的抓到了。
抓不到，那条校验路径就是装饰，此前所有「两条路径一致」的记录一并作废。

例：用内核的块层计数器去校验程序自己数的 I/O 次数，两者逐格一致。
这个「一致」只有在**摘掉直接 I/O 之后、块层计数归零而程序计数纹丝不动**被观测到之后，
才构成证据——否则那个一致也可能是第二条路径在回声第一条。

**这与「每个验证都必须能失败」是同一条纪律作用在校验路径上**：
主检查要证明会红，校验路径同样要证明会红。**只证明前者，等于只做了一半。**

## 喂给多方论证的背景材料，本身要先核

找多个独立来源交叉验证一个推论时，通常要先写一份「已知事实」交给各方。
**那份材料里的每一条外部事实，提问者自己要先核过。**

理由是机制性的：**各方都以它为前提，所以材料里的错误会被所有方一起继承**，
而它们仍然会给出「一致」的结论——**一致因此不再是证据**。

实测：一份背景材料里写着某个现役实现「没有某个字段」，
其中一方自己查到了相反的原文，**却仍然沿用材料里的说法作对照基准**。
最终的一致，是三方一起继承了同一个错误。

**做法**：材料里凡是「某某实现是这样的」这类句子，写进去之前自己现查一遍；
核不动的就标明「未核实」，让各方知道那一条不能当前提用。

## 别的项目怎么做，是线索不是证据

**禁止把其他项目的实现当作直接证据。** 「XFS 就是这么做的」「内核里有先例」
只证明了「有人这么做过」，不证明「在本工程里这么做是对的」。

中间隔着一整套没被检查的前提：它的负载、它的盘上格式、它的并发模型、它的兼容包袱、
它当时要解决的那个问题——任何一条对不上，结论就不迁移。
而这些前提**不会跟着结论一起被引用**，通常也没写在它的代码里，读源码读不出来。

⇒ 外部实现只能进两个位置：**提出假设**、**指出该测哪条路径**。
不许进三次推导（正推 / 反推 / 校验）的任何一步，也不许当作校验路径——
它不是独立路径，它连本工程的被测对象都没碰过。
要当证据，先在本工程里复现出可观测的数据，此后引用那个数据，不是那个实现。

**分清哪一半可以引**：

| 可以 | 不可以 |
|---|---|
| **事实**：「`XLOG_CONTINUE_TRANS` 这个常量存在」「某函数散在 22 个文件 93 处」——可核实、可重跑 | **论证**：「因为 XFS 这么做，所以这么做是对的」 |
| **反证**：某个方案在现役实现里**从未出现过**，是一条要求解释的信号 | **正证**：某个方案在现役实现里出现过，不构成它适合本工程 |
| **机制**：把别家的做法拆成机制，再论证那个机制在本工程的前提下成立 | **搬运**：把结论连同它没写出来的前提一起搬过来 |

⚠️ **「没有任何现役实现走 X 这条路」是本工程最值钱的一类外部信号**——
它不证明 X 错，但它把举证责任压到 X 这一侧：
**要走一条没人走过的路，得说清别人为什么没走。**

⚠️ **引用别家实现时，必须同时写下它与本工程的一处已知差异。**
写不出差异，说明还没读懂那个做法为什么在那边成立，
此时的引用是**搬运**不是论证。

**引用时标明来源与「未在本工程验证」**（`kb-discipline.md`「每条带出处与状态」）。

## 一个假设要能被观测否掉，否则它不是假设

写下假设之后，**先问「什么现象会推翻它」**，答不上来就说明它还没成形，不要拿去建实验。

**排除一个假设，要么有可证伪的观测，要么明说是推的。**
「我想不出别的解释」不构成排除。

## 不许先有结论再建模型

**先挑定结论、再去建一个能得出它的模型，是本纪律要拦的头号形态。**
它不表现为「造假数据」，表现为**每一步都合理、而那些步骤是被结论挑出来的**：
选哪个参数、建模到哪一层、拿谁当对照臂、忽略哪一维——每一处都有得选，
而人只会记住自己选过的那几处里最容易辩护的那一处。

**判据（写下结论之前自问，答不上就还没做完）**：

| 问 | 说不出就是先有结论 |
|---|---|
| 这个模型**先于**我的倾向存在吗 | 说得出「我建它的时候还不知道会得出哪一边」 |
| 我给**另一边**也建了同样认真的臂吗 | 说得出对面那条臂的最好形态是什么、我有没有量它 |
| 反过来的结果我**接不接受** | 说得出「若量出相反的数，我会怎么改结论」——这句话要在跑之前写下 |
| 我有没有**只在一个点**上取值 | 一个尺寸、一个参数、一个负载得出的倍数，不叫「最坏」 |

⚠️ **最容易中招的时刻是「推翻一个旧结论」**：这时人已经有了新方向，
而推翻的快感会让新模型的每一处选择都朝那个方向倒。
**推翻要比确立更严**，不是更松。

⚠️ **稻草人对照臂是这条的典型产物**：给对面那条路挑一个没人会真的采用的实现形态
（「每个条目单独一条记录」这类），量出它很差，然后当成那条路的代价。
**判据**：对面那条臂的形态，**是不是它的支持者会认的那个**。

## 文件系统特有的反推缺口

本工程的多数被测量是**对 / 不对**这样的二值现象。风险不在测量精度，在覆盖：

- **「测试全绿」不等于「实现正确」。** 崩溃窗口可能只有一次写宽，
  没撞上可能只是没遍历到那个崩溃点。要说「崩溃一致性成立」，
  得说清这一轮**本来撞得上吗**——枚举了多少个崩溃点、是不是全部。
- **「checker 没报错」不等于「镜像是好的」。** 也可能是 checker 还没实现那条检查。
  说这句话之前先看 `kb/invariants.md` 里对应条目的实现状态。
