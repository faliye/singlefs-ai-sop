# 陈述外部状态之前，现查一次

**凡是关于「外部世界现在是什么样」的话，说出口之前必须当场跑一条命令确认。**
记忆、kb、上一轮对话、TODO 表，全都只是线索，不是证据。

「外部世界」= 不在本次对话里、可能在我不知情时被改动的一切：

| 要说的话 | 现查的命令 |
|---|---|
| 门禁现在过不过 | 跑 `scripts/gate.sh`，不要从上一轮结果推断 |
| 某个不变量实现了没 | 读 `kb/invariants.md` 的状态列，再 grep checker 源码确认它真的在 |
| 某个决策定了没 | 读 `kb/decisions.md`，看状态是「已定 / 半定 / 待定」哪一个 |
| 工具链 / 环境齐不齐 | 跑 `scripts/env.sh` |
| 别家文件系统是怎么做的 | 现查其文档或源码，并在 kb 里标注来源与「未在本工程验证」 |
| 测试镜像现在什么状态 | 现场跑 checker，不要靠「上次跑过是好的」 |

**不需要现查的**：本次对话里刚读过的文件、纯代码逻辑推导、算术。

## 「它定了没」和「它到底怎么定义的」是两个问题

查过状态列、确认某条决策是「已定」，**不等于知道它定的是什么**。
要拿一条决策去建模、去写检查、去推翻别的结论时，**必须把它的定义逐字读一遍**，
不许照自己的印象建模。

实测：一个实验要测某条决策在新场景下会不会出错，
建模时按自己的理解造了两种可能的语义，测出「两种都会出错」并据此推翻了那条决策。
而**那条决策的正文里早就写着第三种定义**——按它跑，错误恒为零，
整个结论方向是反的。事后回看：状态列查过了，定义没读。

**做法**：引用一条决策去做任何推导之前，把它的定义句原样贴进你的笔记或实验注释里。
贴不出来，说明你在按印象工作。

## 落实

- **改 kb 或 TODO 里任何一行状态时，先跑那一行对应的命令。**
  不查就不要重写它——留着旧的至少还带日期，改一遍等于给错的加了新时间戳。
- 说不出「我是靠哪条命令知道的」，那句话就得写成**推测**，不能写成事实。
- 用户提出的事实性更正**同样要核**，不是照单全收也不是反驳——核完把结果说清楚。
